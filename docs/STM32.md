# Agent Lumos STM32 demo — Linux + C + C++ + Python

This is the **hardware-free, reproducible** v1.1 demo. The sample readings are synthetic and are generated by C++ on the host, not measured by an MCU.

## Prerequisites

Python 3.11+, `gcc`, `g++`, `pip` and a Linux terminal. From repository root:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev,stm32]'
./scripts/stm32_demo.sh
```

### What happens

1. GCC compiles the portable **C11** CRC-16 and frame encoder.
2. G++ compiles a **C++17** `HealthPolicy` and host-only simulated sensor values.
3. Four valid ASCII telemetry frames are passed through a pipe into the **Python OOP** parser and registry. It validates the CRC and fields, rejects repeats, and outputs JSON.

See [stm32-demo-output.txt](stm32-demo-output.txt) for the verified, timestamp-normalized result. The third report intentionally contains an abnormal synthetic voltage and temperature:

```json
{
  "device_id": "stm32-sim",
  "sequence": 3,
  "uptime_ms": 3000,
  "vdd_mv": 3100,
  "temperature_c": 74.8,
  "state": "warn",
  "authenticated": false,
  "integrity": "crc16-error-check-only"
}
```

The `authenticated: false` field matters: a valid CRC is **not** proof of device authenticity.

## Once an actual STM32 is connected

Review [firmware/stm32/README.md](../firmware/stm32/README.md) for board and STM32CubeIDE steps. Use `agent-lumos stm32-read --port /dev/ttyACM0 --max-frames 5` for a direct read-only serial demo. To integrate the board into the local API, set `LUMOS_STM32_PORT` in the untracked `.env` and launch `agent-lumos serve`. Authenticate to the existing API and access `GET /v1/stm32/devices`. Without a board, that endpoint returns an empty array; it does not invent readings.
